Construction · Drawings & Markup

/projects/:id?tab=documents owner (write)

The Drawings & documents register is a controlled drawing register — not a folder of files. Each drawing is a numbered slot; revisions stack under it and exactly one is marked current, so a client (or a trade on site) is only ever shown the current revision, never an older one. From a drawing you can also mark it up — cloud the bit that's wrong, measure it, and raise it as an RFI in one step.

Where: open a construction project → the Delivery stage → the Drawings & documents section (?tab=documents). Adding, revising and marking up are owner-only; collaborators and clients see the current revision of the sheets you've made visible.

The register

Each row shows the drawing number (unique in the project, e.g. A-101), title, discipline, and the current revision (or an amber “No revision uploaded”). A purpose badge is green when the sheet is buildable (issued for construction or as-built) and amber otherwise — so an information-only or superseded sheet can't be mistaken for one you can build from. Expand a row to see its earlier revisions; the owner can Make current on any of them.

Adding a drawing

New document opens the dialog with two ways to fill it:

  • Scan the title block — drop in a sheet and it reads the title block and pre-fills the number, title, scale, discipline and sheet size (snapping to the platform's controlled lists; anything it can't map is reported, not silently dropped). It writes nothing until you confirm.
  • Type it — number, title, kind, discipline, scale, sheet size, and whether the current revision is shown to the client.

A scanned sheet is filed as revision A automatically. Creating is resumable: if the register entry saves but the file upload fails, the entry survives and pressing Create again just re-attaches the sheet.

Revisions

Upload revision suggests the next letter/number and asks for the file, the date printed on the sheet (“Issued on” — deliberately not defaulted to today, because it's the sheet's own date), what it was issued for, and what changed. The new one becomes current; the previous revision is kept and stays viewable. That's the whole point of a register: history is never lost, and everyone downstream sees the same current sheet.

Marking up a drawing → an RFI

What it is — the Mark up action on a drawing opens a viewer where you can cloud, box, arrow, add a note, and measure — then raise the marked region as an RFI. Why it matters — “this dimension doesn't work” is far clearer as a cloud on the exact spot than as a sentence.

  1. Pick the Cloud tool and outline the problem area (double-click to close the cloud).
  2. To measure, first Set scale: click the two ends of something whose real length you know and type that length — the printed title-block scale is deliberately not trusted. Until you've calibrated, the sheet shows “Not to scale — measurements unavailable” and any measurement reads “not measured” rather than a made-up number.
  3. Select your markup, add a “What is wrong with this?” note, and Raise as RFI. It's idempotent — pressing it again returns the same RFI, never a second numbered question — and the drawing then shows an “RFI raised” badge. You can also Export the marked-up sheet as a PDF.

Worked example. A subcontractor flags a clash. Open the current architectural sheet → Mark up → cloud the clash, set the scale off a known 3000 mm grid line, measure the overlap → add the note and Raise as RFI. It lands in the project's Requests register as a numbered RFI, tied to that sheet, with the marked-up PDF attached.

From chat: the drawing register and markup are UI tools — the assistant doesn't operate them.
