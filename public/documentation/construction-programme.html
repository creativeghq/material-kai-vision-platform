Construction · Programme & Baseline

/projects/:id?tab=tasks (Schedule view) owner (edit)

The Programme is a Gantt view of the project's tasks with a real critical path — it works out which tasks have slack (float) and which don't, draws the dependencies between them, and lets you freeze a baseline so you can measure slippage against the plan rather than letting drifted dates quietly become the new plan.

Where: a project → the Delivery stage → the Tasks section (?tab=tasks), then switch the List / Schedule toggle to Schedule. You create tasks in List; you set dates, dependencies and the baseline in Schedule. Editing is owner-only; collaborators view it read-only.

The Gantt

Tasks (and their subtasks) appear as bars against a month timeline, with a Today line, elbow dependency arrows, progress-fill on each bar, and milestone diamonds. The header states “N of M tasks scheduled · K on the critical path” and the overall completion %.

  • Critical path — the tasks with no slack are highlighted; if any of them slips, the finish slips. Non-critical tasks print their float beside the name (e.g. “+3d”); critical tasks show none, because zero float is what makes them critical.
  • Reschedule — an owner drags a bar to move it, or clicks it to edit: mark it a milestone, set start/end and progress, and manage “Runs after” predecessors. A dependency that would create a loop is refused.

Float and the critical path always agree — they come from the same calculation, so a highlighted bar and its printed float can never contradict each other.

The baseline — measuring slippage

What it is — a frozen snapshot of the planned dates. Why it matters — without one, when tasks slip their new dates silently become the plan and the slippage is invisible.

  • Set baseline freezes every task's start/end as “the plan” (it tells you how many tasks it froze).
  • After that, the strip reads either “Against the baseline: nothing late” or “N tasks late, worst X days” — plus “· Y not measured” for any task added since (a task with no baseline is reported as not measured, never as on-time).
  • Re-baseline or Clear when the plan is formally reset.

Worked example. Build the task list, open Schedule, set each task's dates and its Runs after links, then Set baseline. Two weeks in, a delayed delivery pushes a critical task; the Gantt re-flows, the strip reports “3 tasks late, worst 5 days”, and the highlighted critical path shows exactly what's driving the finish date.

From chat: the assistant can add a task (which then appears as a schedulable row here), but it doesn't set dates, dependencies or the baseline — those are done in the Schedule view.
