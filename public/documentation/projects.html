Projects

/projects /projects/:id

A project is the top-level container that ties together everything for one piece of work — the moodboards, presentation sheets, quotes and people involved — and gives you a single place to assemble and share a polished deliverable with the client.

What Projects are for

Where a moodboard is the working surface and a quote is a single document, a project sits above both. It groups all the boards, sheets and quotes for one client or job, keeps the people involved in one place, and is where you produce the finished package you hand over. If you run work by client or by room, the project is your home base for it.

Projects are module-gated — if you don't see Projects in the navigation, the module isn't enabled for your workspace.

The list page

The /projects page shows every active project as a card. From here you can:

  • New Project — create a project and name it for the client or job.
  • Show archived — reveal projects you've archived so they're out of the way but still findable.
  • Open a project — click any card to go to its detail page.

Inside a project

A project's detail page (/projects/:id) is organised into tabs that cover the work and its deliverables. The set you see depends on your role — some tabs are owner-only or shown only when their module is enabled.

The headline capability is the Client View.

Client Views owner-only

A Client View is a project-level deliverable that bundles selected presentation sheets — drawn from any of the project's boards — into one client-ready package: a PDF plus a revocable online page. It's the thing you actually send to the client.

The online page can carry things a static PDF simply can't:

  • 3D walkthrough — an explorable Marble world embedded right in the page.
  • Lighting moods — switch the hero render between lighting presets so the client sees the space in different light.
  • Live FF&E table — a furniture, fixtures & equipment list pulled live from a linked quote, so it stays accurate.
  • Inline approve / comment — the client can sign off or leave feedback directly on the page.

How you build and share one

  • Pick and order sheets — choose which sheets to include and the order they appear.
  • Toggle embeds — decide which extras (3D walkthrough, lighting moods, live FF&E table, approve/comment) to switch on.
  • Generate the PDF — produce the downloadable version of the package.
  • Share or revoke — copy the share link to send to the client, or disable it at any time to cut off access.

Anything the client does on the online page — an approval or a comment — comes back into the project, so you can read their feedback in one place. For more on how the public-facing page behaves, see Public pages & sharing.

The Client View is one level above a single board's deck: it can combine sheets from several boards in the project, and adds the interactive online surface on top of the PDF.

Inviting collaborators & clients

You can invite other people — teammates or the client — into a project. They receive an invite link (/projects/invite/:token) that opens a public landing page; once they're signed in, they accept the invite and gain access. Shared users see the project marked as shared and get a reduced set of tabs (the owner-only tabs stay private).

Archiving

When a project is finished, archive it to hide it from the active list without deleting anything. Use Show archived on the list page to bring archived projects back into view at any time.

In short: create a project per client or job, do the design work in moodboards and price it in quotes, then assemble the chosen sheets into a Client View and send the share link. Their feedback returns to the project.
