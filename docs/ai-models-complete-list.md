  - Saved-search semantic dedupe

  - Quick validation tasks
- **Context**: 200,000 tokens
- **Cost**: $1 input / $5 output per 1M tokens
- **Performance**: 3× faster than Opus, 90%+ accuracy

### 3. HuggingFace Inference Endpoints

#### SLIG (SigLIP2 SO400M, 768D projected) — VISUAL EMBEDDINGS
- **Use Cases**:
  - 5 specialized 768D visual embeddings per image (visual, color, texture, style, material)
  - Image-text similarity via similarity mode
  - Visual search
  - Multi-vector search
- **Dimensions**: 768D per type (halfvec in VECS)
- **Modes**: `zero_shot`, `image_embedding`, `text_embedding`, `similarity`
- **Endpoint**: `mh-slig` (namespace: basiliskan), serves the custom HF model `basiliskan/slig`. Underlying architecture per the production env (`VISUAL_EMBEDDING_PRIMARY_MODEL=google/siglip2-so400m-patch14-384`) is SigLIP2 SO400M (native 1152D); the endpoint applies a 1152D → 768D projection so every downstream consumer sees a uniform 768D output (`SLIG_EMBEDDING_DIMENSION=768`).
- **Cost**: HuggingFace endpoint with auto-pause
- **Performance**: 768D output is dimensionally aligned with all VECS visual collections; the previous direct-1152D SigLIP-SO400M collections (without projection) were retired 2026-04 as 100% orphans

**Environment variables**: `SLIG_ENDPOINT_URL`, `SLIG_ENDPOINT_TOKEN`, `SURYA_ENDPOINT_URL`, `SURYA_ENDPOINT_NAME`, `SURYA_NAMESPACE` (cover the Surya-2 endpoint on HuggingFace). To run Surya on **Modal** instead, set `SURYA_PROVIDER=modal` + `SURYA_MODAL_URL` + `SURYA_MODAL_API_KEY` (see the Surya-2 section's provider switch below).

**Embeddings generated by SLIG**:
1. **Visual** (768D, halfvec) → `image_slig_embeddings` (producer key `visual_768`) — the only collection produced by SLIG.

The four aspect collections (color/texture/style/material) are Voyage `voyage-4` 1024D text embeddings of deterministic strings derived from `VisionAnalysis`:

2. **Color** (1024D Voyage) → `image_color_embeddings` (producer key `color_aspect_1024`) — `VisionAnalysis.colors[]`
3. **Texture** (1024D Voyage) → `image_texture_embeddings` (producer key `texture_aspect_1024`) — `VisionAnalysis.textures[] + finish`
4. **Style** (1024D Voyage) → `image_style_embeddings` (producer key `style_aspect_1024`) — `VisionAnalysis.style + surface_pattern + applications`
5. **Material** (1024D Voyage) → `image_material_embeddings` (producer key `material_aspect_1024`) — `VisionAnalysis.material_type + category + subcategory`

Plus an **Understanding Embedding** (1024D Voyage AI from Claude Opus 4.7 `vision_analysis` JSON) → `image_understanding_embeddings` for spec-based semantic search.

#### Surya-2 (Datalab `surya-ocr-2`) — STRUCTURAL-PASS BACKBONE (layout + OCR + figure boxes)
A single 650M vision-language model that returns the page layout (region labels + bboxes), OCR'd text, and figure boxes in one `/v1/chat/completions` call. **Replaced YOLO DocParser + Chandra OCR + `merge_layout` (all deleted 2026-06-13).**
- **Use Cases**:
  - Stage 1 document-level structural pass (runs before discovery — structure-first), persisted to `document_layout_analysis` (`processing_version='surya-2'`)
  - Phase 3 per-image OCR + icon-metadata + admin re-OCR (via `ocr_service` → `run_structural_pass` on the crop)
- **Contract**: full-page `high_accuracy_bbox` mode → top-level `<div data-label= data-bbox=>` blocks; bbox **0-1000 normalized** (parsed to 0..1 in `surya_blocks.py`). 19 layout labels map onto the existing `region_type` vocab; `Image`/`Figure`/`Diagram` are the product-crop sources.
- **Retry strategy**: 3 attempts at temperatures 0.0 / 0.2 / 0.4 (jitter breaks sticky-prose state)
- **Failure marker**: `OCRResult.method='surya_failed'` — consumers must check `method`, not emptiness
- **Per-attempt metrics**: `surya_ocr_metrics` table (carries a `provider` column = which GPU host served the call)
- **GPU host — pluggable provider switch (`SURYA_PROVIDER`)**: the inference contract (OpenAI-compatible vLLM `/v1/chat/completions`) is identical across hosts; only the lifecycle differs. `app/services/pdf/endpoint_providers.py` implements both as `EndpointProvider`s and `SuryaEndpointManager` delegates to the selected one:
  - `huggingface` (default) — HF Inference Endpoint (eu-west-1); SDK resume / poll-for-GPU / scale-to-zero. Vars: `SURYA_ENDPOINT_URL`, `SURYA_ENDPOINT_NAME`, `SURYA_NAMESPACE`, `HUGGINGFACE_API_KEY`.
  - `modal` — Modal-hosted vLLM (`mivaa-pdf-extractor/modal_app/surya_vllm.py`); Modal owns autoscaling (auto-wake on first request, auto-drain after `scaledown_window`). Warmup = `/health` probe; scale-to-zero = Modal's idle clock. Vars: `SURYA_MODAL_URL`, `SURYA_MODAL_API_KEY`, `SURYA_MODAL_MODEL_NAME`. Deploy: `modal deploy modal_app/surya_vllm.py` (see that folder's README). Chosen as the reliable-capacity alternative after HF's serverless pool repeatedly failed to allocate a GPU.
  - Switch hosts with one var, no code change. `/health` (admin AI-health surface) reports the active `provider`.
- **Replaced**: YOLO + Chandra (2026-06-13); earlier pytesseract + EasyOCR (2026-05)
- **Known residual**: `Image`/`Figure` blocks are not OCR'd (text baked inside a photo is not read) — a `voyage-multimodal-3` page embedding is the planned follow-up.

## 📈 Model Usage by Feature

### PDF Processing Pipeline (named stages — numbers retired)
- **Layout + Page OCR + figure boxes (Stage 1, structure-first)**: **Surya-2** structural pass — one call per page, runs BEFORE discovery
- **Discovery**: Claude Opus 4.7 or GPT-5 — reads Surya's reading-order text from the cache (not raw `get_text`)
- **Chunking**: **Claude Sonnet 4.6** (was Qwen pre-2026-05-01)
- **Vision (primary)**: **Claude Opus 4.7 via tool use** (was Qwen pre-2026-05-01 — but Qwen had been 404-ing for months)
- **Vision (validation pass)**: triggered when primary confidence < threshold OR primary fails. DEFAULT/HIGH_ACCURACY profiles use Claude Opus 4.7; FAST/COST_OPTIMIZED profiles use Claude Haiku 4.5. Driven by `classification_validation_model` in `ai_config`.
- **Phase 3 OCR (per-image)**: **Surya-2** block OCR, runs AFTER vision. Consumed by icon-metadata extraction + image-search labels (NOT by chunker, NOT a vision_analysis prompt input).
- **Visual Embeddings**: SLIG (SigLIP2 SO400M (768D projected), 5×768D)
- **Understanding Embedding**: Voyage AI voyage-4 (1024D, parallel with Visual Embeddings)
- **Text Embeddings**: Voyage AI voyage-4 (1024D, sole embedder)

### Web Scraping Integration
- **Product Discovery**: Claude Opus 4.7 (default), GPT-5, or Claude Haiku 4.5

### XML Import
- **Field Mapping**: Claude Opus 4.7

### Interior Design Generation
- **Text-to-Image**: 7 Replicate models (FLUX, SDXL, etc.)
- **Image-to-Image**: 3 production-ready Replicate models
- **Parallel processing**: 3 concurrent generations

### Saved Searches Deduplication
- **Similarity Analysis**: Claude Haiku 4.5

### Price Monitoring
- **Discovery (Stage A)**: Perplexity Sonar-Pro + DataForSEO Merchant (parallel) — Greek marketplaces (Skroutz/Bestprice/Shopflix) + Idealo (DACH/IT/UK/ES/FR)
- **Verification (Stage B)**: Firecrawl + Pydantic `PriceExtraction` schema
- **Identity classifier**: Claude Haiku 4.5 with few-shot from `match_corrections`

### B2B Manufacturer Search
- **Tool**: Anthropic `web_search_20250305` (claude-haiku-4-5 + beta header)

## 🔄 Model Fallback Strategy

### Vision Analysis
1. **Claude Opus 4.7 via tool use** (PRIMARY — schema-locked)
2. No fallback — Anthropic-only post-2026-05-01

### Product Discovery
1. Claude Opus 4.7 (primary)
2. GPT-5 / GPT-4o (alternative)
3. Claude Haiku 4.5 (tertiary, lower accuracy)

### OCR
1. **Surya-2 with retry-jitter** (3 attempts, temps 0.0/0.2/0.4)
2. No fallback — `OCRResult.method='surya_failed'` set on all attempts failing

### Visual Embeddings
1. SLIG SigLIP2 cloud endpoint (primary)
2. 3-attempt retry on dim-mismatch
3. Skip if all attempts fail (graceful degradation, image flagged)

### Text Embeddings
1. Voyage AI voyage-4 (primary, sole) — 1024D
2. OpenAI text-embedding-3-small (legacy CI changelog only — pinned to 1024D in code if ever called, so wrong-dim writes are impossible)
3. Understanding path has **no** fallback — disabled to prevent VECS collection drift
